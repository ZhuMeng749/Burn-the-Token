# 用制作反馈更新镜头库与判断方法

## 每次反馈如何落地

保留用户原话、对应作品版本与作用范围，记录：

问题位置 → 参考镜头 ID / 修订与源时间码 → 已观察差异 → 修正动作 → 复检证据 → 后续反馈。

不要只写“更高级”“审美不行”。拆成可定位的构图、比例、字体、字厚、遮挡、运动阶段、声画落点等差异。“素材可以”只确认素材；“继续”通常确认当前推进范围，不代表所有细节已经验收。用户要求保留、回退或暂缓的部分，按最新指令执行。

## 三种信息，写到三个位置

| 信息 | 保存位置 |
|---|---|
| 原片观察的补充或纠正 | 用 `update-shot` 更新镜头卡，保留旧修订 |
| 某作品的适配评价、个人偏好 | 项目反馈记录，以及 `use` 的使用备注 |
| 有证据支持的通用流程改进 | 用户明确要求维护 Skill 时，更新相应规则 |

不要把私人素材路径、完整对话或源视频放入公开 Skill。不要把某个项目的字体、风格和偏好固定成所有人的默认答案。

## 可复用的判断方法

- **自行加了参考没有的装饰**：按对应阶段比较；移除缺乏参考依据的横线、卡片、光效等元素。
- **立体程度和人物覆盖不够**：分别检查字面与侧面、厚度、透视、光向、景深、遮挡边界和人物占比。
- **镜头衔接生硬**：用户要求优化时，从动作、方向、形状、视线、声音和语义寻找承接；明确暂缓时保留当前衔接。
- **呈现方式重复**：查看同一项目的镜头使用记录；区分统一的视觉母题与重复使用同一整套特效。
- **批量制作细节下降**：扩大制作批次不能省略每镜参考、运动阶段、差异记录和复检。
- **音效单一**：按动作角色、材质、瞬态、尾音、密度和能量选声，实际试听本地素材；文件数量、峰值和导出成功不代表听感合格。

## 更新与证据边界

优先修改已有规则，避免不断叠加重复禁令。软件、滤镜或实现方式无法从画面确认时，标记为实现假设。

可复用的代码组件单独管理代码版本和验证记录；一张参考镜头卡并不等于已经实现好的特效组件。维护 Skill 时保留备份、更新版本，并检查链接、模板与说明一致。

结构校验和工具测试证明流程与数据操作可用，不能证明视频的动态、音效、参考还原程度或用户已验收。
